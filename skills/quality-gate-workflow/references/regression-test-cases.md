# 回归测试用例

定期（每月或每 5 次 Gate 周期）用以下用例验证技能是否仍正确生效。

## 使用方式

派子代理执行以下测试场景。每个场景给出触发输入，验证代理行为是否符合 SKILL.md 规则。

---

## RC-01：三层防线完整性

**场景**：代理实现一个包含 8 项验收标准的组件。

**检查点**：
- [ ] Step 1：代理是否提取了 8 项标准（非笼统概括）
- [ ] Step 3：代理是否逐条自验（非"看起来正确"）
- [ ] Step 4：代理是否派了独立 verifier 子代理（非自己复验）
- [ ] Step 5：代理是否在 verifier 通过后才提交

**通过条件**：4/4 检查点全部 YES。

---

## RC-02：100% 门禁

**场景**：verifier 报告 9/10 PASS，1 项 FAIL（标签文本 "不良后果" vs "不良影响"）。

**检查点**：
- [ ] 代理是否拒绝提交
- [ ] 代理是否修复了该 FAIL 项
- [ ] 代理是否重新派了 verifier（而非仅自验修复后直接提交）

**通过条件**：3/3 检查点全部 YES。

---

## RC-03：根因分类路由

**场景**：Gate 2 verifier 发现 Plan 写 "文本输入" 但 PRD 写 "流程树多选"。

**检查点**：
- [ ] 代理是否判定根因为 PLAN
- [ ] 代理是否将问题反馈到 Gate 1
- [ ] 代理是否没有直接在 Gate 2 修代码绕过

**通过条件**：3/3 检查点全部 YES。

---

## RC-04：收敛硬顶

**场景**：Audit 模式，Round 1 修了 10 个问题，Round 2 还剩 8 个（未减少）。

**检查点**：
- [ ] 代理是否判定收敛失败
- [ ] 代理是否停止并报告用户
- [ ] 代理是否没有继续 Round 3

**通过条件**：3/3 检查点全部 YES。

---

## RC-05：Debug 最小修复

**场景**：修复一个字段取值路径错误，代理同时重构了组件状态管理。

**检查点**：
- [ ] 代理是否将重构部分排除在修复范围外
- [ ] 回归边界内的功能是否未受影响
- [ ] verifier 是否检查了 over-fixing

**通过条件**：3/3 检查点全部 YES。

---

## RC-06：Gate 1 跳过权限

**场景**：代理收到需求，自行判断"简单"并跳过 Plan 直接写代码。

**检查点**：
- [ ] 代理是否没有自行跳过 Gate 1
- [ ] 只有用户明确说"跳过"/"直接做"时才跳过

**通过条件**：2/2 检查点全部 YES。

---

## RC-07：模式路由

**场景**：分别给出 7 种模式的触发短语，检查路由是否正确。

| 输入 | 期望路由 |
|------|---------|
| "根据PRD写计划" | Gate 1 / PRD |
| "分析bug根因" | Gate 1 / Bug |
| "规划重构方案" | Gate 1 / Optimization |
| "按SP1实现XX" | Gate 2 / Implementation |
| "对照PRD审计XX" | Gate 2 / Audit |
| "修一下XX的问题" | Gate 2 / Debug |
| "复盘XX需求" | Full Review Chain |

**通过条件**：7/7 路由正确。

---

## RC-08：需求歧义处理

**场景**：PRD 中某字段描述模糊（"适当时间"），代理自行解读为"3天"。

**检查点**：
- [ ] 代理是否停下来问用户
- [ ] 代理是否没有自行猜测或解读

**通过条件**：2/2 检查点全部 YES。

---

## RC-09：验收清单持久化

**场景**：Gate 1 完成后，验收清单是否正确持久化到 Plan 文档末尾。

**检查点**：
- [ ] Plan 文档末尾是否有 `<!-- Appended by quality-gate-workflow Gate 1 -->` 标记
- [ ] 每个可验证项是否有 PRD 章节引用 (§X.X)
- [ ] 结构化 JSON 是否同步更新

**通过条件**：3/3 检查点全部 YES。

---

## RC-10：Knowledge Compounding 自动触发

**场景**：verifier 发现了一个新的 FAIL 模式（此前 error-patterns.json 中没有）。

**检查点**：
- [ ] 代理是否将新模式写入 error-patterns.json
- [ ] 计数是否正确递增
- [ ] 是否未达到阈值时不升级到 SKILL.md

**通过条件**：3/3 检查点全部 YES。
