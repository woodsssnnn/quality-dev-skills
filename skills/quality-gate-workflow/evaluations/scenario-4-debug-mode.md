# Scenario 4: Debug 模式最小修复

## 目的

验证 Debug 模式是否正确定义修复标准、执行最小修复、无 over-fixing。

## 模拟 Bug

用户报告：任务列表中"任务状态"列的 Tag 颜色映射错误。

实际代码：
```tsx
// TaskTable.tsx 第 42 行
const statusColorMap = {
  待处理: 'blue',
  进行中: 'blue',   // BUG: 应为 orange
  已完成: 'green',
  已关闭: 'gray',
};
```

PRD 要求（§6.2）：任务状态 Tag 颜色映射 = 待处理:blue / 进行中:orange / 已完成:green / 已关闭:gray。

**trigger_input**: "修一下任务列表的任务状态 Tag 颜色，进行中应该是橙色不是蓝色"

## 预期行为

### D1: 定义修复标准

- [ ] 输出 `[qgw:debug:D1] 定义修复标准 — Bug: 任务状态 Tag 颜色映射错误`
- [ ] 定义三要素标准：
  - **症状**：进行中状态的 Tag 颜色为 blue，与 PRD §6.2 要求的 orange 不符
  - **预期**：进行中状态 Tag 颜色改为 orange，其余 3 个状态颜色不变
  - **回归边界**：待处理/已完成/已关闭的 Tag 颜色不变，表格其余 4 列不受影响
- [ ] 标准具体可验证（非"修好颜色"）

### D2: 最小修复

- [ ] 输出 `[qgw:debug:D2] 最小修复 ...`
- [ ] 仅修改 `statusColorMap` 中 `进行中: 'blue'` → `进行中: 'orange'`
- [ ] 不修改其他代码（不重构、不调整其他颜色、不优化组件结构）
- [ ] 修改范围严格限定在 1 行代码内
- [ ] 不"顺便"修改文件格式、注释风格、导入顺序

### D3: 自验

- [ ] 输出 `[qgw:debug:D3] 自验 ...`
- [ ] 验证症状消除：进行中 Tag 颜色现在为 orange
- [ ] 验证预期达成：代码与 PRD §6.2 一致
- [ ] 验证回归边界：其余 3 个状态颜色未被改动
- [ ] 输出 `[qgw:debug:D3] ✅ 症状消除 + 预期达成 + 回归边界完整`

### D4: verifier 子代理 → 提交

- [ ] 输出 `[qgw:debug:D4] verifier 验证`
- [ ] 实际调用 `Task` 或 `Agent` 工具派发 verifier
- [ ] verifier 检查：修复正确性 + 无回归 + 无 over-fixing
- [ ] verifier 确认修改仅 1 行，无其他改动
- [ ] 输出 `[qgw:debug:D4] ✅ 修复正确, 无回归 → 提交`

## 评估标准

| 编号 | 检查项 | 权重 |
|------|--------|------|
| D1 | 三要素标准（症状/预期/回归边界）完整且具体 | 必须 |
| D2 | 修改严格限定在标准范围内（1 行） | 必须 |
| D3 | 三项验证全部通过 | 必须 |
| D4 | verifier 实际派发 + 确认无 over-fixing | 必须 |

**通过条件**：全部 4 个检查项 PASS。

## 常见失败模式

以下行为应被视为 FAIL：

1. **Over-fixing**：修改了 statusColorMap 以外的代码（如重构成枚举、提取常量）
2. **模糊标准**：症状描述为"颜色不对"而非"进行中状态 Tag 颜色为 blue 而非 orange"
3. **跳过回归检查**：未验证其余 3 个状态颜色不变
4. **跳过 verifier**：D3 自验通过后直接提交，未派 verifier
5. **顺便重构**：修改导入顺序、调整代码格式、添加注释
